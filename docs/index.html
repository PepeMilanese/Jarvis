    Under the hood

    Small parts, sharp contracts

    A stdlib-only Python supervisor, one long-lived Claude Code session that triages, and short-lived workers that do the real work — each piece with one job.

    🧭

    Supervisor

    Python, stdlib only. Runs the dispatcher as claude -p with stream-json in and out and stdin held open forever; logs every event and restarts it.

    python -m jarvis dispatcher
    🧠

    Dispatcher

    A long-lived headless Claude Code session with an operating manual on its system prompt. Small questions it answers itself; anything that changes state or takes over a minute becomes a worker job.

    manual/DISPATCHER.md
    ⌨️

    Launcher CLI

    Picks a free slot (max 3 — a 4th waits until a slot frees), writes a brief, launches a detached watchdog and returns one JSON line in seconds.

    start · status · answer · stop · result · cleanup · quota
    🛡️

    Watchdog

    One per running slot. Owns the worker, snapshots its process tree every 15 s, reaps leftovers, classifies the outcome, writes the ledger and frees the slot.

    jobs/s1.json … s3.json
    📜

    Worker contract

    One turn, foreground only, ask before anything irreversible — and finish with a summary or a question block that carries a proof: line.

    JARVIS-SUMMARY · JARVIS-QUESTION
    ⏰

    Durable schedule

    One-shots, intervals, cron and the built-in watch entry in one file. Fires only between turns and survives restarts.

    --at 02:00 · --in 90m · --every 30m · --cron "30 7 * * 1-5"
    🎙️

    Offline Whisper

    faster-whisper (CTranslate2, CPU, int8) with large-v3-turbo, ~1.6 GB in its own venv. No speech-to-text service ever hears the audio.

    python -m jarvis stt <file>
    📊

    Quota readout

    The Claude subscription's 5-hour and weekly windows — % used and reset time — degrading to one honest line, never a stack trace.

    python -m jarvis quota

    Self-healing

    Every guard is a scar

    Each of these broke for real in production. The supervisor now catches it, fixes it, and sends at most one honest line to the phone.

    53dispatcher sessions brought up by the supervisor
    46fresh-context restarts — 36 scheduled at 06:45, 10 on demand
    5×poller-gone restarts, fired for real
    1×stolen bot caught and taken back
    1×logged-out outage, one alert, one “back online”
    01

    Deaf session

    4 of 4 restarts

    WHAT BROKEThe session snapshots its MCP servers at the first message. A kickoff sent before the Telegram poller was up gave a session that never hears a thing — one ignored its owner for 24 h.

    THE FIXWait for the poller, settle 3 s, kick off, read the init event; kill and retry (backoff 15 → 300 s) any session whose channel isn't connected with the reply tool.

    02

    Poller gone

    fired 5×

    WHAT BROKEThe Telegram poller process vanished while the session lived on — a healthy-looking session that could no longer hear.

    THE FIXPoller missing for 90 s while the session lives → restart the session.

    03

    Stolen bot

    73 min silent

    WHAT BROKEOne getUpdates consumer per token: any other Claude Code session opened in the folder started its own poller and took the bot — behind a green log.

    THE FIXThe poller must be a descendant of this session, re-proven every 5 min (pids get reused); stray pollers are swept before launch.

    04

    Logged out

    1 outage

    WHAT BROKEA refused token refresh wiped the CLI login; every message got a 401 behind a channel that still said “connected”.

    THE FIXNo session starts while claude auth status says logged out; a session answering “Failed to authenticate” is killed; one alert goes straight through the Bot API, then one “back online”.

    05

    Process-tree safety

    pid reuse

    WHAT BROKEWindows parent pids go stale and get reused — one reaper walked from a reused pid into system processes.

    THE FIXNever taskkill /T. A child must be younger than its parent, and only known tree-process names are ever stopped.

    06

    No inherited pipes

    2 h hang

    WHAT BROKEAn inherited handle once hung the dispatcher for two hours, waiting on a launcher that had long finished.

    THE FIXThe watchdog is started fully detached, so the launcher returns in seconds — every time.

    Scheduled tasks

    User-level, “run only when logged on”, all launched through a tiny run_hidden.vbs — no console window ever flashes.

    TaskTriggerWhat it does
    Jarvis-Dispatcherlogon + 45 sthe supervisor — the task lives exactly as long as it: single instance, no time limit, restart on failure 3×
    Jarvis-Dispatcher-Restartdaily 06:45stop poller and supervisor, restart — a fresh context every morning
    Jarvis-Dispatcher-Healevery 15 min at :05 :20 :35 :50start the dispatcher if its supervisor is gone, silent otherwise (never at :45 — it once raced the 06:45 restart)
    Jarvis-Boot-Reportlogon + 3 minproof of what came up on its own: minutes since boot, clean or unclean shutdown, which processes and settings stuck
    CI-Runner-1 / -2this PClogon + 60 s, every 15 minself-hosted GitHub Actions runner loops; a named mutex per slot means a repeat trigger never doubles a loop, and a dead loop is replaced within 15 min
    Autostart appsthis PClogon + 30 sdesktop apps and a terminal session

    The four Jarvis-* tasks ship with the repo: windows\install-tasks.ps1 installs them, windows\always-on\check.ps1 audits every always-on setting read-only.

    Sign-in without a human

    Sysinternals Autologon keeps the password as an encrypted LSA secret — never plaintext in the registry. Change the password, re-run Autologon. A real session, not services: the AI login, Docker, cloud drive and bot poller are all per-user.

    AutoAdminLogon = 1NoLockScreen = 1CONSOLELOCK 0
    🌙

    Never sleep

    No standby, no hibernate, monitor stays awake; hibernation and Fast Startup off, so a shutdown is a real one and every boot is clean. Wake timers allowed.

    powercfg /change standby-timeout-ac 0powercfg /change hibernate-timeout-ac 0powercfg /change monitor-timeout-ac 0powercfg /hibernate offHiberbootEnabled = 0
    🛑

    Windows Update can't reboot it mid-job

    Automatic install off by policy, notify only, no auto-reboot with a user logged on, active hours stretched to 23:00 → 17:00. Updates go in by hand about monthly — cheap now that reboots are survivable.

    NoAutoUpdate = 1AUOptions = 2NoAutoRebootWithLoggedOnUsers = 1
    ♻️

    CI runners that recycle

    Two ephemeral GitHub Actions runners in an isolated WSL2 distro — own Docker, no Windows drive, no interop. Each registration serves one job, then re-registers with a fresh 1-hour token minted on the host; the work folder is wiped before and after.

    recycle one idle slot at a timenever wsl --shutdown mid-job

    Remote safety net

    Tailscale in unattended mode keeps the PC reachable for remote desktop even with nobody signed in — and a remote logon itself creates the session that starts everything.

    Wedge detection without timers

    No time cap. No budget cap. Evidence.

    Ceilings only ever killed jobs that were working. The dispatcher is the stop — and it needs three signals to agree.

    Working — leave it alone

    • pid aliveyes
    • transcript growing
    • step line movingstep: reading the failing test

    → keep going — even at hour 36

    Wedged — stop it

    • pid aliveyes
    • transcript growing
    • step line movingstep: running the suite unchanged

    → wedged across several polls — the dispatcher stops it

    wedged = pid alive AND transcript stopped growing AND step line unchanged across several polls. Elapsed time and cost alone are never evidence.

    Lessons learned

    Eleven lessons, each paid for

    Every one of them comes from a real incident.

    1. A session is not a service.

      Anything per-user needs a real logon — autologon plus logon tasks, not “run as SYSTEM”.

    2. Verify the channel, not the process.

      A live process with a connected-looking plugin can still be deaf.

    3. Ownership, not liveness.

      “Is the poller alive?” is the wrong question when any other session can take the bot.

    4. No timers on working jobs.

      Budget and time ceilings only ever killed jobs that were working. Detect wedges from evidence — a stalled transcript under a live pid.

    5. Headless means one turn.

      A worker that backgrounds a command and ends its turn is dead — foreground only, at most 9 minutes per wait.

    6. Write between turns.

      A message written into a running turn gets merged into it — so the durable schedule fires only when the session is idle.

    7. Every task carries its own acceptance test.

      proven right by: on the way in, proof: on the way out — evidence that does not rest on the agent's word.

      → task · proven right by: the suite passing in CI← summary · proof: CI green on the PR head

    8. Never trust a scraped number.

      PR numbers read from prose were wrong three times in one morning; only numbers the job itself created are shown as verified.

    9. Speech-to-text can invent instructions.

      A glossary prompt made Whisper append a plausible task nobody said; a forced language silently translates. No glossary — and a heard= warning when the audio was another language.

    10. Never taskkill /T.

      Parent pids go stale. Walk the tree yourself and require a child to be younger than its parent.

    11. Fail soft, alert once.

      The quota readout and the outage alert both degrade to one honest line instead of a stack trace — and the phone gets one alert per outage, not a flood.

    Offline Whisper

    Talk to it. Transcribed on the PC.

    About 20 voice memos so far, all transcribed on a 6-core CPU with no GPU — then echoed back verbatim before Jarvis acts.

    🔒

    Local speech-to-text, by design

    Transcribed on the PC — no speech-to-text service ever hears the audio. faster-whisper on CTranslate2, CPU, int8, with the large-v3-turbo model (~1.6 GB) in its own venv. The memo is downloaded, transcribed, echoed as 🎤 I heard: … — and the audio file is deleted.

    No confirmation step: Jarvis acts at once, you read the echo while the job already runs, and you say “stop” if it misheard.

    Lesson 9: a glossary prompt made Whisper append a plausible task nobody said, and a forced language silently translates. No glossary, and a heard= warning when the audio was another language.

    Quick start

    Run your own in five steps

    A sketch of the setup — the README has the full walkthrough, including the always-on recipe.

    78 tests · Windows + Linuxsupervisor: Python stdlib onlyMIT licence

    1. Clone the repo

      git clone https://github.com/PepeMilanese/Jarvis && cd Jarvis

    2. Create your bot and connect the channel

      Make a bot with @BotFather, then — inside the Jarvis folder, in claude — install Claude Code's official Telegram channel plugin and give it the token. Pair your account once, then switch the bot to allowlist: only allow-listed users get through.

      /plugin install telegram@claude-plugins-official
      /telegram:configure <your-bot-token>

    3. Check the machine

      The doctor checks what Jarvis needs and tells you what is missing.

      python -m jarvis doctor

    4. Add offline speech-to-text (optional)

      Sets up faster-whisper and the large-v3-turbo model in its own venv.

      python -m jarvis stt-setup

    5. Start the supervisor — then make it permanent

      Run it once in a terminal; on Windows, install the scheduled tasks so it survives every reboot, and audit the always-on settings read-only.

      python -m jarvis dispatcher
      powershell -NoProfile -ExecutionPolicy Bypass -File windows\install-tasks.ps1 -BootReport
      powershell -NoProfile -ExecutionPolicy Bypass -File windows\always-on\check.ps1
